## 40：产线多了「物料图」视图

产线页现在是三个视图：**流程列表**（每台机器的数字）、**机器图**（原来的流程图）、**物料图**（新）。
物料图里物料才是格子、机器是两个物料之间的转换，每个方块上写它自己的买入/产出/消耗/余额，箭头就是那个物料，
往回走的物料单独走紫色回流道。

**这一版的物料图还没在真机上确认过**：JVM 截图里文字仍然会压到格子边上，分不清是测试环境没字体还是画法本身，
下一轮定这件事。**配方包没变，不用重下。**

## 这一版（39）：配方标题不再是英文 id，名字里的颜色代码清掉了

- **配方标题显示中文机器名**。以前是 `gtceu:alloy_blast_smelter`，现在是**合金冶炼炉**。
  配方类型是机器的注册名，而包里机器名是物品（`gtceu:alloy_blast_smelter` = 合金冶炼炉），
  多方块两者同名可直查，单方块（`gtceu:macerator` ↔ `gtceu:lv_macerator`）通过机器表接上。
  配方选择器的一级分组也跟着变中文了。
- **1,926 个物品的名字里带着 Minecraft 颜色代码**（`§6§o茶`、`§4§lMAX§r电力活塞`），
  游戏里它们渲染成颜色，文本框里就是一个一个字符——App 之前显示的是 `§6§o茶`。
  现在包里所有名字都是纯文本，**带 § 的名字 = 0**。
- **详情弹窗多了「复制」**：产出 ← 输入（流体带 mB、概率产出带百分比），第二行机器名 + 耗时/EU/电压，
  第三行配方 id。
- 顺手修了一个会在真机上犯的错：查机器名时一次性绑了 2,100 个 id，而 SQLite 每条语句最多 999 个变量
  ——这个查询会直接失败，配方列表就永远转圈。是截图测试超时把它逼出来的，现在按 400 一批。

**配方包要重下**（名字改了，第 5 代）。

## 37：代次读错导致误报旧包；161 个物品补名字

- **App 一直在误报「配方包是旧版」**：包里写的代次读错了对象（读成 `pack.buildGeneration`，
  实际在 `pack.json` 顶层），于是任何包都存成"第 0 代"，**你刚导完包它就让你再导一次**。
- **161 个物品没有名字**（界面显示 `molten_hastelloy_n` 这种注册名）：124 个是流体，
  打包脚本给流体起名的步骤**排在写物品表之后**，名字算完就丢；24 个是 GT 工具（名字只在指南针树里）；
  13 个退化成 id 可读形式。现在**无名物品行 = 0**，导入测试会断言这一点。
- `DL` 按钮改成「下载包」。

## 35：卡住的产线不再让你去调一个没有正确值的参数

- 我原来标注的"唯一未修缺陷"（互锁循环解不出来）**是记录错了**：把两条物料守恒写出来就知道
  `y = x`、净产出恒为 0，本来就达不到；错的是提示语让你去找瓶颈。现在无解时会**把所有机器和原料上限
  拆掉再解一次**：仍然无解就是结构性的，直接说"和机器数、原料量都无关"。
- 循环产线在物料表里看不见的问题也修了：原来按"净流量不为 0"过滤，而线内循环的物料净流量正好是 0，
  一条正常工作的回收线看着像什么都没发生。现在按"有没有在流动"显示，并标「线内循环」。

- **tag 类型的物料槽**（`#forge:hydrogen`）还没有图标和数量。
