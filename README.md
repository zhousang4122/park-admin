# McRecipe 构建产物

安卓端「GTL 配方检索 + 产线设计」的发布包。**只放构建产物，源码不在这里。**

## 下载

| 文件 | 大小 | 更新频率 |
| --- | --- | --- |
| `McRecipeBrowser-0.1.0-34-g47686ed.apk` | 16.66 MB | **每次发版都变**——修 bug、加功能 |

**这一版两个都要下**，原因见下。

## 这一版修了什么（34）——旧的配方包会被指出来，而不是接着用

你上次报的「没名字的材料、搜不到的材料」，根子不在 App，在**你手机上导入的那个包是旧的**。
包在 31、32 两版里补了物品表和流体行，App 却无从知道手上的包是哪一代，于是照旧用——表里没有
的行就退化成注册名（英文）。**表现出来像是 App 的 bug，实际是数据缺行。**

- 包里现在写了 `buildGeneration`（当前第 3 代），App 导入时读进来，**比当前版本旧就在配方页顶部
  出一条提示**，写明是第几代、缺什么、去下载页重导 `gtl-full.mcrp` 就好。
- **只提示，不拒绝。** 旧包大部分问题照样答得出来，直接不让用会把"暂时没法重导"的人卡死；
  但不能一声不响地用着，让你以为东西丢了。
- 顺手修了包自己的一个错：`pack.json` 里的 `counts.items` 是**在补物品行之前**写下的，所以一直
  比实际行数少。现在在所有补行之后才统计。

> **这一版必须重导包**：数据库结构从 4 升到 5（多一列 `build_generation`），Room 会直接重建库，
> 也就是**必须重新导入 `gtl-full.mcrp`**，否则 App 里是空的。重导之后提示就不会再出现。

## 更早的版本

- **32**：流体和"有名字但没配方"的材料补进物品表——**你说的四氧化锇、酸性锇这类就是这一版找回来的**。
- **31**：修掉一万条左右的**假产物 id**（`tagprefix.small_dust` 这种），配方从 53,533 恢复到 55,190 条。
- **30**：说清楚每个机器为什么没跑；停了的机器显示「每份配方」吃什么产什么；目标达不到时不再返回空结果；定投没填输入时说明；标题不再掉到配方 id。
- **29**：物品列表真的能翻页；收起卡片保留输入输出；图标失败会明说；超频按 tick 算。
- **28**：节点标题用产物名。

**两个文件是分开的，就是为了让你大部分时候只下 APK。** 只有在我明确说「包也换了」的时候才需要重下 `.mcrp`；没说的话，旧的包照用。

**装完 App 之后要导入 `.mcrp`**（第一次必须导）。数据库结构在大版本会变，如果 App 提示要重新导入，那就是包也变了。

### 怎么判断这次要不要重下 mcrp

在 GitHub 上看 `gtl-full.mcrp` 这一行的「上次提交时间」——**没变就不用重下**，因为 Git 按内容存文件，内容没变时代码库里的记录也是同一个。

## 32 版修了什么——流体和"有名字但没配方"的材料能搜到了

上一版修了假 id，这一版修的是**另一类洞**：物品表里根本没有这一行。

- **流体不是物品**，所以物品表里原本没有它——除非 GT 恰好为它注册了一个同名物品。结果就是：配方里写着"四氧化锇"当输入，**点它没反应，搜它也搜不到**。现在 **124 个流体**补了行，名字从包自己的表里取（有翻译的桶名去掉"桶"字 → `material.*` → 流体状态键），所以「酸性锇溶液」这类现在显示中文。
- **530 个材料有名字但没有任何配方用到它**，因此也没进物品表。现在作为"仅名字"条目收进去，标了 `noRecipe`，App 会说明"这个材料存在，但本包里没有它的配方"，而不是给你一个空白页。**四氧化锇就是这么找回来的。**
- 还删掉了一个我自己加错的过滤条件：我原本跳过了已经有"粉/锭"的材料，理由是"那是固体、物品表里有"——**结果正好把要报的这几个流体全跳过了**。

另外顺手核对了你说的另一个：**沉淀铑粉**的真名是 `再沉淀铑粉`，配方链完整：

```
再沉淀铑粉 x7 →(化学反应釜 / 大型化学反应釜) 铑粉 + 氯化铵粉 x6 + 氢
```

**32 版之后的状态：被引用但物品表里没有的 id = 0 条。** 我加了个审计脚本专门回答这个问题（这个问题我答错过两次，所以做成了工具而不是靠眼看）。

## 30 版修了什么

- **说清楚每个机器为什么没跑。** 以前只有一句话「当前目标不需要它的产出」，而这句话大约一半情况是错的——机器没跑可能是**原料输入是 0**（要去填「外部输入」），也可能是**产物已经被线里别的机器做了**，这两种情况的解决办法是相反的。现在分四种说法。
- **停了的机器显示「每份配方」吃什么产什么**，而不是一排 0。以前「输入 0 / 输出 0」和「这配方本来就没材料」是分不清的。
- **目标达不到时不再什么都不显示。** 以前这种情况下求解器返回空结果，界面上每张卡都是灰的、没有输入输出也没有原因。现在会列出机器和它们的产能，让你看出是哪一步卡住。
- **定投模式没填输入时直接说清楚**，而不是给你一屏 0。
- **标题不再是配方 id。** 从配方弹窗加进来的节点没有"产物"信息，标题就掉到配方 id 上了。现在用**它配方的第一个产物**当名字。

## 已知缺口

- **并行数要手填**。GT 的并行数在匹配时由机器和并行仓现算，导出时 2137 台机器的修饰器全是 lambda，读不出常量。界面上给的是并行控制仓等级参考。
- **成环产线的目标行有一个未修的缺陷**，单测里用 `@Ignore` 记着，无环线路不受影响。
- **真机界面没有自动化验证过**（开发环境起不了模拟器），所以手感和布局需要你实际用一遍。
