## 这一版修了什么（32）——流体和"有名字但没配方"的材料现在能搜到了

上一版修了假 id，这一版修的是**另一类洞**：物品表里根本没有这一行。

- **流体不是物品**，所以物品表里原本没有它——除非 GT 恰好为它注册了一个同名物品。结果就是：配方里写着"四氧化锇"当输入，**点它没反应，搜它也搜不到**。现在 **124 个流体**补了行，名字从包自己的表里取（有翻译的桶名去掉"桶"字 → `material.*` → 流体状态键），所以「酸性锇溶液」这类现在显示中文。
- **530 个材料有名字但没有任何配方用到它**，因此也没进物品表。现在作为"仅名字"条目收进去，标了 `noRecipe`，App 会说明"这个材料存在，但本包里没有它的配方"，而不是给你一个空白页。**四氧化锇就是这么找回来的。**
- 还删掉了一个我自己加错的过滤条件：我原本跳过了已经有"粉/锭"的材料，理由是"那是固体、物品表里有"——**结果正好把要报的这几个流体全跳过了**。

另外顺手核对了你说的另一个：**沉淀铑粉**的真名是 `再沉淀铑粉`，配方链完整：

```
再沉淀铑粉 x7 →(化学反应釜 / 大型化学反应釜) 铑粉 + 氯化铵粉 x6 + 氢
```

**现在的状态：被引用但物品表里没有的 id = 0 条。** 我加了个审计脚本专门回答这个问题（这个问题我答错过两次，所以做成了工具而不是靠眼看）。

### 怎么判断这次要不要重下 mcrp

在 GitHub 上看 `gtl-full.mcrp` 这一行的「上次提交时间」——**没变就不用重下**，因为 Git 按内容存文件，内容没变时代码库里的记录也是同一个。

## 这一版修了什么（30）

- **说清楚每个机器为什么没跑。** 以前只有一句话「当前目标不需要它的产出」，而这句话大约一半情况是错的——机器没跑可能是**原料输入是 0**（要去填「外部输入」），也可能是**产物已经被线里别的机器做了**，这两种情况的解决办法是相反的。现在分四种说法。
- **停了的机器显示「每份配方」吃什么产什么**，而不是一排 0。以前「输入 0 / 输出 0」和「这配方本来就没材料」是分不清的。
- **目标达不到时不再什么都不显示。** 以前这种情况下求解器返回空结果，界面上每张卡都是灰的、没有输入输出也没有原因。现在会列出机器和它们的产能，让你看出是哪一步卡住。
- **定投模式没填输入时直接说清楚**，而不是给你一屏 0。
- **标题不再是配方 id。** 从配方弹窗加进来的节点没有"产物"信息，标题就掉到配方 id 上了（就是这个一直英文的毛病）。现在用**它配方的第一个产物**当名字。

## 更早的版本

- **29**：物品列表真的能翻页；收起卡片保留输入输出；图标失败会明说；超频按 tick 算（50t / 2.5s，最低 1 tick）。
- **28**：节点标题用产物名。

- **物品列表真的能翻页了。** 之前那个自动加载的判据读的是一个不会更新的旧值，所以永远不触发，列表停在前 200 个；现在改成随状态刷新的写法，并且底部有「加载更多」按钮。
- **收起卡片不再吃掉输入/输出。** 上一版把卡片收成一个标题，等于把列表最有用的一行——点材料看配方——删了。现在收起只藏机器选择、电压和长尾速率，两边的材料列表都在，各显示 4 行，并提示还有多少。
- **图标失败会明说。** 以前图集读取失败只会把每个物品画成一个点，什么提示都没有。现在会尝试 RGB_565 重新解码、必要时从暂存包重新解出图集，实在不行就在界面上写明原因。另外图集和配方包不匹配时**不画**——画错图集会把格子的像素对应到别的物品上，那比没图更糟。
- **超频按 tick 算。** 配方耗时是整数 tick，超频在 tick 上整除、最低 1 tick。之前按秒连续除，会算出 0.3125s 这种机器不可能有的时间。现在显示「50t / 2.5s」，可以跟 JEI 对。
- **节点标题用产物名**，不再是 `gtceu:packer_package_...` 这种配方 id。
- **机器表进了包。** 节点上会列出能跑这条配方的机器，点一下就用它的电压；并行数在 GT 里不是字段（读不出来），所以界面只给出并行控制仓的等级表。

## 已知缺口

- **并行数要手填**。GT 的并行数在匹配时由机器和并行仓现算，导出时 2137 台机器的修饰器全是 lambda，读不出常量。界面上给的是并行控制仓等级参考。
- **成环产线的目标行有一个未修的缺陷**，单测里用 `@Ignore` 记着，无环线路不受影响。
- **真机界面没有自动化验证过**（开发环境起不了模拟器），所以手感和布局需要你实际用一遍。
